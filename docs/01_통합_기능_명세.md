# 학업 통합 학습 앱 — 통합 기능 명세서 (웹앱 + Android APK)

- 상태: **설계 확정본 v1.1** (2026-11-20, 배포 플랫폼 수정)
- 요구사항 추적: `02_설계_결정_추적표.md` (질문 1–157)
- 목적: Windows PC와 iPad에서는 **웹앱(PWA 설치 가능)**, Android 스마트폰에서는 **APK 설치형 앱**으로 사용하는 개인 학업 관리 서비스. **React 기반 단일 코드베이스**를 공유한다. (157개 선택 완료 후 사용자 추가 지시)
- 구현 방식: **전체 화면과 디자인 먼저 완성 → 이후 실제 기능·서버·동기화 연결** (Q157A)
- 기존 로컬 프로젝트(사용자 제공 이전 맥락): `C:\Users\USER\Projects\my-ipad-app`; **Claude Code가 실제 경로·코드·설치 상태를 반드시 재확인**
- 문서의 확정 사항과 기술 제안은 구분한다. [확정] = 사용자가 결정한 기능, [구현 제안] = 개발 과정에서 검증·조정 가능한 기술적 제안.

## 0. 최우선 불변 조건

1. **사용자가 고른 1~157번 설계를 변경하지 않는다.** 특히 최근 결정이 앞선 내용을 수정했다면 최신 결정을 우선한다.
2. 한국 시간대 `Asia/Seoul`로 모든 학습일을 계산하며, 학습일 경계는 **매일 05:00**이다(Q52, Q156). 홈의 ‘오늘’과 시험·수행평가 D-Day도 이를 따른다(Q53–55). 그러나 실제 시작·종료·마감의 타임스탬프를 변조하지 않는다.
3. **확정된 실제 학습 기록 간 시간 중복 저장을 금지**한다(Q84 최신 수정). 과거 Q75C의 겹치는 기록 허용은 폐기된다. 오프라인 중 충돌 후보는 별도 보존하고 사용자가 해결해야 정상 확정한다(Q82, Q138).
4. 학습 **시간 목표에는 자습만** 반영한다(Q70). 학원 출석 시간은 별도로 기록하며 전체 통계에서 자습과 함께 볼 수 있으나, 시간 목표 달성에는 쓰지 않는다(Q41–43).
5. 일반 할 일은 반복 생성하지 않는다(Q59). 학원 숙제는 주간 반복 템플릿과 자동 생성 기능을 유지한다(Q36–40).
6. 일반 할 일의 완료는 **완료/미완료**만 관리한다. 완료 시각·지연 사유·지연 완료 통계는 제공하지 않는다(Q58).
7. **Google Drive 원본은 앱에서 삭제하지 않는다**(Q77). 앱의 파일 연결 정보만 삭제 또는 휴지통 처리한다.
8. **모의고사 시험 기록에는 파일 연결 기능을 제공하지 않는다**(Q89). 파일은 문제집·수행평가·일반 할 일 등에 연결 가능하다(Q15).
9. UI는 미니멀, 라이트/다크/시스템 테마. 기본 캘린더는 **일간 보기**, 스마트폰은 하단 메뉴, iPad·PC는 사이드바, 첫 실행은 **진짜 빈 상태**(Q152–155).
10. 데이터 손실이나 자동 수정이 발생할 수 있는 작업은 사용자가 확정한 복원·충돌·삭제 규칙을 준수한다.
11. **플랫폼 추가 요구사항**: Windows PC·iPad는 Cloudflare Pages의 웹앱을 사용하고 Android는 Capacitor 패키징 APK를 사용한다. 기능 요구사항과 서버 계정·D1 데이터는 공유한다. Android 독립 앱을 새 프런트엔드로 중복 개발하지 않는다. (사용자 추가 지시; Q1~157 변경 아님)

## 1. 제품 범위 및 화면 구조 [확정]

### 1.1 정보 구조
- 기능 중심 탐색: 홈, 캘린더, 할 일, 공부 기록·타이머, 문제집, 시험·성적, 수행평가/프로젝트, 학원, 분석·목표, 학습 자료, 학교 시간표, 설정·보관함·휴지통.
- 수능/내신을 별도 앱 영역으로 분리하지 않는다. 공통 과목 계층, 태그, 기간, 유형의 필터로 탐색한다(Q1, Q2, Q21).
- 검색: 할 일·문제집·프로젝트·시험·Drive 연결 파일의 **이름**을 전역 검색(Q113). 보관 기록은 기본 제외하고 사용자가 포함 설정 가능(Q119). 본문 전체 검색은 범위 아님.
- 홈은 오늘 일정·할 일·타이머·주요 목표·다가오는 시험과 수행평가 D-Day·간단한 학습 요약 중심. 세부 통계는 별도 화면. 홈 위젯 자유 배치 없음(Q20).
- 시험·수행평가가 **오늘/내일**인 항목을 일반 할 일보다 최우선으로 노출. 일반 할 일은 높음→보통→낮음, 동일 우선순위에서는 마감 빠른 순(Q34–35, Q127). ‘어제 미완료 자동 이월’ 기능 없음.

### 1.2 반응형 UI
- **스마트폰**: 하단 탭 + 필요한 나머지는 더보기/메뉴. **iPad·PC**: 고정/접힘 가능 사이드바. 상호작용은 터치와 마우스·키보드 모두 지원.
- 디자인: 조용한 미니멀 구성, 충분한 대비, 밀도 조절, 다크 모드, OS 테마 연동(Q154). 기본 캘린더 = 일간 보기(Q152).
- 온보딩 강제 없음, 예시 데이터도 생성하지 않음. 각 화면에 명확한 빈 상태(Empty State)와 ‘추가하기’ 조작 제공(Q155).
- 앱 내부 알림만 사용하며 푸시 알림 없음(Q14). 정상 동기화 상태 배지/상시 로그 화면 없음(Q109). 데이터 충돌 시 해결 화면은 예외적으로 노출.

### 1.3 플랫폼별 배포 및 UI [확정된 추가 요청]
- **PC / iPad**: Cloudflare Pages에 배포한 동일 웹앱. Windows 브라우저와 iPad Safari에서 사용하며, 필요하면 홈 화면 설치형 PWA도 가능.
- **Android 스마트폰**: 같은 React/Vite 빌드 산출물을 **Capacitor** Android WebView 앱으로 패키징하여 APK 설치. Android Studio/Gradle로 빌드·검증. 웹앱에서 호스팅 중인 URL을 단순 원격 WebView로 감싸는 방식은 기본 배포안이 아님.
- **한 소스 트리 / 두 배포 산출물**: `dist/`로 웹빌드 → Cloudflare Pages, 동일 `dist/` → `npx cap sync android` → Android 앱 빌드. 웹 및 APK의 화면, 도메인 모델, API 계약을 공유하고 플랫폼별 API 차이는 어댑터로 분리.
- **인증**: Google 웹 로그인과 Android 네이티브/시스템 브라우저(Credential Manager/Custom Tabs 등) 기반 로그인은 다른 클라이언트 구성이 필요할 수 있다. **임베디드 Android WebView 내부 Google OAuth 금지**. 서버에서 플랫폼별 토큰 및 사용자 식별을 검증하여 동일 사용자 계정에 매핑. Drive 동의는 로그인과 별도.
- **오프라인/저장소**: 웹은 IndexedDB/Dexie, Android도 지원 여부를 검증해 공통 repository 계층을 사용. Android WebView 저장소의 보존성과 오프라인 복구를 실기기에서 시험하며 필요 시 Android 영속 저장 어댑터 별도 검토. D1 동기화와 충돌 정책은 플랫폼 공통.
- **업데이트**: 웹앱 배포 업데이트와 Android 앱 바이너리 업데이트는 별개. Android React 코드가 바뀌면 APK를 다시 빌드·설치해야 한다.
- **UI**: Android 스마트폰의 하단 내비게이션, 시스템 뒤로 가기, 상태바·안전 영역(Safe Area), 소프트 키보드 및 터치 입력을 검증. iPad·PC 사이드바 유지.
- 추가 상세 기준: `05_플랫폼별_배포_전략.md`.

## 2. 과목·분류

- 과목 계층: 대분류 → 세부 과목. 예: 수학 → 미적분Ⅰ(Q2).
- 학습 기록은 수능 태그, 내신 태그를 **둘 다**, 하나만, 또는 **둘 다 없이** 저장 가능(Q1, Q118). 전체 시간은 하나의 실제 공부 구간을 한 번만 집계.
- 과목 이름 변경 시 과목 ID를 보존하고 관련 과거 기록에도 새 이름 표시(Q125).
- 과목 삭제 시 과목만 30일 휴지통으로 이동. 과거 학습 기록·연결 식별자는 보존하고 복원 시 다시 연결(Q126).

## 3. 캘린더·학교 시간표·계획

### 3.1 계획 시간 블록
- 개별 학습 계획은 과목, 수능/내신 태그(선택), 학습 활동(선택), 계획 시작·종료 시각을 포함.
- 블록을 드래그 이동·크기 조절하거나 날짜·시간을 직접 입력해 수정(Q68).
- **학습 계획 블록끼리 시간 중복 시 저장 차단**(Q69). 학교·학원 수업 일정과 학습 계획이 겹치는 것은 경고 없이 허용(Q102).
- 계획이 실현되지 않았으면 원래 계획만 보존, 실제 학습량 0으로 계산; 별도 ‘미실행’ 관리·재배치 기능 없음(Q51).
- 계획 변경 시 기존 실제 학습 기록의 시각은 절대 따라 변경하지 않음(Q133).
- 이미 학습 기록과 연결된 블록 삭제 시 계획만 휴지통으로 이동하고 실제 기록은 유지(Q141).
- 삭제된 계획을 복원할 때 다른 계획과 겹치면 복원할 블록의 날짜·시간을 먼저 수정한 후 복원(Q144).
- 수동으로 입력한 학습 기록도 사용자가 기존 시간 블록을 지정해 연결 가능(Q147).

### 3.2 일정·시간표
- 반복 캘린더 일정 생성 가능(Q11). 반복 일정 **수정** 시 '이번만 / 이번 및 이후 / 전체' 중 선택(Q131); 반복 일정 **삭제**는 선택한 한 회차만 삭제(Q142).
- 학교 시간표는 월~금/교시·시간을 다루는 **현재 시간표 1개만 유지**, 변경 시 덮어쓰기(Q36, Q106). 특정 날짜의 예외 수업은 정기 시간표를 바꾸지 않고 별도의 캘린더 일정으로 추가(Q99).
- 학교 정규 수업은 일정 전용이며 학습 시간 통계에 포함되지 않음(Q43).

## 4. 타이머·실제 학습 기록

### 4.1 입력 및 측정
- 실시간 타이머와 수동 입력 제공(Q9). **수동 입력은 시작·종료 일시 모두 필수**; 총분만 단독 입력 불가(Q74).
- 실제 자습 기록은 과목과 태그, 문제집/프로젝트/할 일 등 활동에 선택적으로 연결(Q10).
- 공부 중 과목을 바꿀 수 있다(Q44). 전환할 때 새 과목의 수능/내신 태그·연결 활동을 확인하는 창을 보여주고 **전환 확정 시점**에 이전 과목 구간을 마감하여 새 구간을 시작(Q47).
- 계획 블록에서 ‘공부 시작’하면 과목·태그·활동을 타이머에 적용하고 실제 기록을 계획에 연결. 독립 타이머 허용(Q48).
- 계획에서 시작된 타이머라도 **과목 전환 후의 새 과목 기록은 원래 계획 블록과 분리**(Q76).
- 계획 종료 시각이 되어도 타이머는 계속 실행해 초과 실제 시간을 기록(Q49). 다음 계획이 시작되면 앱 안에서 계속 공부/전환 선택 안내만 제공하고 자동 전환하지 않음(Q50).
- 학습·휴식·전체 경과 시간을 구분. 휴식은 학습 합계에서 제외(Q45).
- 앱 종료/화면 잠금에 의존해 백그라운드에서 계속 도는 타이머를 가정하지 않는다. 저장된 시작/전환/휴식 시각을 이용해 경과를 복원하고, 앱 재실행 시 중단 기간의 공부/휴식 여부를 확인·수정(Q46).

### 4.2 기기 간 단일 타이머 및 시간 충돌
- **계정당 실행 중 타이머 한 개**. 다른 기기에서 이어받을 때 명시적 소유권 이전 확인, 이전 기기는 읽기 전용(Q71, Q148).
- 오프라인에서 충돌된 타이머 구간은 삭제하거나 두 개를 동시에 확정하지 않는다. 충돌 후보 상태에 안전 보존하고 재연결 시 해결 화면 제공(Q82).
- 확정된 실제 학습 구간끼리 겹치는 데이터는 저장 불가(Q84). 기존 기록 시간 수정 중 겹치면 어느 기록을 수정할지 선택하는 충돌 편집 UI를 제공하고 겹침 해소 후 확정(Q138).
- **통합 집계는 동일 실제 공부 구간을 중복 집계하지 않는 원칙**을 유지. Q75의 '중복 기록 허용' 선택은 Q84의 후속 수정으로 폐기.

### 4.3 학습일 및 목표 집계
- 모든 학습일(Daily Study Day)의 경계는 `Asia/Seoul` 05:00, 변경 설정 없음(Q52, Q156). 시간 구간이 05:00을 넘으면 학습일별로 분리 집계; 원본 시각은 보존.
- 새벽 05:00 전 홈 화면 ‘오늘’에는 전날 학습일의 일정·할 일·통계를 표시(Q53). **실제 일정·제출 시각은 바뀌지 않음**.
- 시험·수행평가 D-Day는 동일 05:00 경계로 계산하고 남은 시간(예: 7시간)을 추가로 표시하지 않음(Q54–55). 상세에서는 실제 날짜·시각 확인.

## 5. 학원 강좌·수업·주간 숙제

- 학원/강좌/과목/강사 태그, 정기 수업 요일·시각, 수업 예외(휴강·보강) 지원(Q36, Q40).
- 학원 수업은 출석 여부만 기록하고 예정 수업 시각을 불러와 실제 학습 시간을 수정할 수 있다(Q41–42, Q107). 별도의 지각·조퇴 사유/출결 분류는 없음. 출석 확인 전에는 예정 시간만으로 실제 학습 시간 집계하지 않음.
- 학원 수업은 자습과 분리 통계·전체 통계에 포함되지만 **학습 시간 목표에는 포함하지 않음**(Q70).
- 주간 숙제 묶음을 학원 강좌마다 정기 수업 일정과 동기화하여 자동 생성하고, 반복 숙제 템플릿을 지원(Q37–38). 마감일은 다음 실제 수업일 기준(Q37, Q40).
- 개별 주차의 숙제 편집은 그 주에만 적용, 템플릿은 불변(Q39).
- **템플릿 자체를 바꾸면 이미 생성된 미래 주차의 미완료 숙제도 업데이트**(Q130). 단 사용자가 특정 주차에서 직접 수정한 필드는 보존하고 나머지 템플릿 추종 필드만 갱신(Q134). 과거 완료 기록은 보존.
- 수업이 전혀 없는 주차에는 정기 주간 숙제 **새로 생성하지 않음**(Q137). 이미 숙제가 생성된 이후 휴강이 등록되면 **기존 숙제는 유지하고** 다음 실제 수업일로 마감일 자동 변경(Q140).
- 강좌 삭제 시 강좌와 **미완료 주간 숙제**는 함께 30일 휴지통으로 이동(Q129). 완료 숙제는 보존하며 과거 학원명·강좌명도 표시(Q136).
- 인강/온라인 강좌 전용 관리 기능은 현재 확정 범위에 포함되지 않음(Q36).

## 6. 일반 할 일·하위 체크리스트

- 일반 할 일은 제목, 과목/태그(선택), 마감일(선택), 우선순위 높음/보통/낮음, 완료 여부를 관리(Q34, Q58, Q146). 일반 할 일의 자동 반복 생성은 없음(Q59).
- 마감 시각은 선택. 날짜만 등록된 경우 **마감일 다음 날 05:00**부터 기한 초과 판정(Q56–57). 실제 시각이 입력되어 있다면 그 시각 적용.
- 하위 체크리스트는 선택적 **1단계**만 지원, 각 하위 항목에 선택적 마감일을 지정해 캘린더에 표시(Q60–61). 하위 우선순위는 상위 항목을 상속(Q63).
- 오늘 마감인 하위 항목은 상위 할 일 아래 묶어 보여주고 펼치기 가능(Q64).
- 상위 완료를 **직접 체크**하면 남은 하위 작업도 모두 완료 처리(Q62). 문제집 Part가 연결된 경우 아직 미완료 Part가 있으면 수동 완료 범위 확인(Q33): 상위만 / 남은 Part까지 함께.
- 하위 작업이나 직접 연결된 Part가 전부 완료되면 자동 완료. 둘 다 존재하면 **두 그룹 모두 완료**해야 자동 완료(Q32, Q60, Q65).
- **자동 완료**된 상위 항목의 하위 항목/Part 완료가 취소되면 상위도 자동 미완료(Q66). 사용자가 상위 완료를 **직접 취소**하면 하위 항목·Part 체크는 유지하고 즉시 다시 자동 완료시키지 않음(Q67).
- 완료 항목은 기본 목록의 **접힌 별도 영역**에 표시(Q115). 과거 완료 시각·지연 사유·지연 완료율 통계 없음(Q58).
- 상위 항목 삭제 시 하위 항목도 함께 30일 휴지통으로 이동(Q121), 연결 문제집 Part 자체는 삭제하지 않음.

## 7. 문제집(Workbook)·Part

- 구조: 문제집 → 중단원 → 해당 중단원별 가변 개수의 Part(Q4). 각 Part는 완료/미완료 체크(Q5); 회독/다회독 관리 없음(Q6).
- 중단원별 Part 개수 입력으로 번호 자동 생성; 중단원/Part 개수 목록을 붙여넣어 일괄 생성 가능(Q90).
- 복수 Part 선택 일괄 완료/취소, 중단원 전체 완료/취소 지원(Q93).
- 등록 후 Part 추가/삭제 가능하며 기존 완료 체크 보존, 삭제 전 확인(Q92). **다른 기록에 연결된 Part는 삭제 금지**(Q94).
- 문제집 전체 Part가 완료되면 문제집 자동 완료(Q91). 완료된 문제집에 새 미완료 Part 추가 시 진행률 재계산·문제집 미완료로 되돌림(Q101).
- 문제집을 휴지통으로 보내도 외부에서 연결된 할 일/계획/학습 기록은 보존하고 참조 ID 유지(Q81). 영구 삭제 후에도 과거 학습 기록에는 문제집명 등 최소 기록 스냅샷 보존(Q150).
- 학습 자료(Drive 파일)는 문제집에 연결 가능. 시험 기록 자체에는 파일 연결 불가(Q15, Q89).

## 8. 학교 수행평가 프로젝트

- 과목, 제목, 마감, 배점/평가 기준 설명, 세부 단계 및 기한, 제출 상태, 총점·획득 점수 지원(Q7, Q105). **평가 기준별 획득 점수 입력 기능 없음**(Q105).
- 세부 단계 완료와 실제 제출 여부는 **별개**(Q104).
- 세부 단계 ↔ 일반 할 일 선택 연결 및 완료 동기화(Q120). **한 일반 할 일은 최대 하나의 수행평가 단계**에만 연결(Q122).
- 연결된 단계와 할 일의 마감일은 공유·양방향 변경 반영(Q124). 세부 단계만 삭제하면 일반 할 일 유지·연결만 해제(Q123).
- 프로젝트 전체 삭제 시 프로젝트와 연결된 일반 할 일·하위 작업 모두 휴지통 이동(Q128). 프로젝트 복원 시 함께 삭제된 할 일·하위 작업 및 연결 자동 복원(Q135).
- 시험/수행평가가 오늘·내일이면 홈 최상단에 표시(Q35). D-Day 05:00 기준(Q54).

## 9. 시험·성적·오답 분석

### 9.1 학교 지필 평가
- 중간/기말 지필 성적은 연도·학기·과목·시험일·원점수·등급 및 추이 중심으로 단순 기록(Q8). 상세 채점/OCR 파일 업로드 기능 없음.
- 시험 범위는 여러 교재의 중단원·Part를 연결 가능(Q30). 연결 범위의 **모든 고유 Part가 완료**되어야 범위 전체를 완료로 판정(Q31). 같은 Part가 여러 경로에서 연결되더라도 중복 집계 금지.
- 시험 범위가 연결된 중단원에 새 Part가 생기면 해당 시험 범위에 추가할지 확인(Q139).

### 9.2 모의고사/수능형 시험
- 과목별로 시험 독립 등록: 출제 연도·월·기관·과목·시험 원래 날짜를 구분(Q22, Q29).
- 같은 과목 시험에 첫 응시/여러 재응시를 연결하며 실제 풀이 날짜와 성적·오답은 응시 회차마다 별도 관리(Q22).
- 기본 통계는 **첫 응시만** 포함; 전체 회차/재응시만 필터 선택 가능(Q23).
- 성적은 **원점수·표준점수·백분위·등급 중 어떤 항목이든 선택 입력**(Q86). 미입력 점수를 0으로 대체하거나 임의 변환하지 않음. 성적 추이 그래프의 표시 지표도 전환 가능(Q96).
- 과목별 목표 등급 및 목표 점수 지표(원점수/표준점수/백분위 중 하나) 설정(Q112, Q116).
- 성적·문항 데이터는 수동 입력만 제공, OCR/CSV 업로드 없음(Q28). 시험지/정답/해설 Drive 파일 연결 없음(Q89).

### 9.3 오답 분석
- 간편 기본: 틀린 문항 번호와 원인 분류 **1개**(Q24, Q26). 원인 목록은 기본 제공 + 사용자 추가/수정/비활성화, 안정적인 분류 ID 유지(Q25). 선택적 짧은 분석 메모(Q87).
- 선택적 상세 모드: 전체 정답표, 문항별 배점·단원·정오 여부 기록 가능(Q24).
- 오답 목록 편집 즉시 저장하되 별도 Draft 상태 없음(Q100). **총 문항 수 입력 후 사용자가 오답 입력 완료를 명시적으로 확정**해야 미기재 문항을 정답으로 해석(Q95, Q132). 확정 전에는 미입력과 정답을 혼동하지 않음.
- 확정 후 총 문항 수 변경 시 확정 상태를 유지하고 정오 판정·통계 재계산(Q145). 범위 밖 문항번호는 명확한 입력 오류로 안내하고 수정 전에는 불가능한 정답 판정을 확정하지 않음.
- 응시 회차별 동일 문항의 오답 변화를 비교하고 점수·등급 추이를 함께 제공(Q88). 별도 오답 복습 스케줄러/복습 체크 없음(Q27).

## 10. 목표·통계

- 일간·주간·월간 시간 목표 및 수량 목표(완료 Part 수·완료 할 일 수)를 지원(Q12). 전체 및 과목별 목표는 각각 **독립 설정/평가**(Q110, Q117).
- **시간 목표는 자습 시간만 반영**한다. 학원 시간은 학원/전체 통계에는 포함할 수 있지만 목표 달성 계산에는 포함하지 않음(Q70).
- 100% 초과 달성률 표기 허용(Q111). 과거 목표값 수정 가능, 변경 시 과거 달성률 재계산(Q108).
- 시각화: 학습 시간, 목표, 계획 대 실제, 문제집 진행률, 시험 성적·오답 원인, 수행평가 프로젝트(Q13). 필터: 기간, 과목, 수능/내신, 첫 응시/재응시 등 적합한 축.
- 수능·내신 두 태그가 모두 부여된 한 세션은 필터 결과 각각에 표시될 수 있지만 전체 통계에서는 **중복 합산 금지**(Q1).
- 학교 정규 수업은 학습 통계 대상 아님(Q43).
- 지난 학기 보관된 기록은 기본 목록에서 숨기되 장기 통계에는 포함(Q97–98). 보관함에서 바로 수정 가능(Q143).
- **설계 간 기술 의존성**: Q58에서 완료 시각 기록과 지연 통계를 제외했지만 Q12의 '일별 완료 건수 목표'에는 날짜 귀속 기준이 필요하다. 구현 제안: 사용자가 보는 지연 완료 기능 없이, 집계 전용 `completed_study_day`(날짜만)를 내부 이벤트 메타데이터로 유지한다. 정확한 시간(timestamp)은 할 일 완료 정보로 표시·분석하지 않는다. 세부 기준은 구현 전 문서에 명시하고 데이터 무결성을 테스트해야 한다.

## 11. Google Drive 파일

- Google 로그인은 앱 계정 인증용; **Drive 파일 접근 동의는 별도**로 요청(Q15, Q17).
- 원본 파일은 Drive에 있고 앱에는 선택 파일의 ID·이름·유형·경로/상위 폴더 표시정보·접근 상태·연결 분류 등 메타데이터만 저장한다(Q15).
- 문제집·프로젝트·할 일 등 지원되는 기록과 연결. **시험 기록에는 파일 연결 없음**(Q89).
- 파일명·위치가 바뀌면 권한 범위 내에서 자동 메타데이터 갱신(Q83); 권한 취소/접근 실패 시 연결 정보 보존·'접근 불가' 표시(Q103).
- 앱에서 파일 삭제/해제 시 **앱 내부 연결 정보만 삭제**, 실제 Drive 파일은 절대 삭제하지 않음(Q77). 앱 내 삭제는 30일 휴지통 정책을 따른다(Q79).
- JSON 복원 시 연결 메타데이터를 복원하되, 실제 파일 접근을 다시 검증하고 필요하면 Google Drive 권한을 재요청(Q151).

## 12. 삭제·보관·백업·복원

- 삭제 가능한 앱 내부 기록·계획·문제집·성적·프로젝트·파일 연결 정보 등은 **30일 휴지통** 후 영구 삭제(Q72, Q79). 외부 Drive 원본 및 Google 계정은 휴지통 정책 대상이 아님.
- 일반 상위 할 일 삭제 시 하위 항목 함께 휴지통 이동(Q121); 프로젝트 전체 삭제 시 연결된 할 일도 함께 이동하고 복원 시 함께 복구(Q128, Q135).
- 학원 강좌 삭제 시 미완료 숙제만 함께 삭제, 완료 숙제는 역사 기록 유지(Q129, Q136).
- 지난 학기 데이터는 사용자가 수동 보관. 기본 목록에서 숨기지만 통계에는 포함, 보관함에서 열람/수정 가능(Q97–98, Q143). 이는 휴지통과 다른 기능.
- **JSON**: 전체 앱 내부 데이터를 백업 내보내기·파일 가져오기 복원(Q73, Q78). 복원은 기존 데이터를 백업 내용으로 **전체 대체**(Q80), 가져오기 전 구조 검증 및 기존 데이터 안전 백업 권고. Google 인증 비밀/토큰은 백업에 포함 금지.
- **CSV**: 학습 기록·통계 전체를 내보낸다. 필터별 일부 범위 추출 UI는 없음(Q73, Q85).

## 13. 인증·서버·오프라인·동기화

### 확정 제품 동작
- Google 계정 로그인, Cloudflare D1 서버 DB를 중심으로 자동 기기간 동기화(Q17).
- 인터넷 없이 일정·할 일·문제집 체크·타이머·학습 기록을 읽고 수정한 뒤 온라인 복귀 시 동기화(Q18). Drive 원본은 일반적으로 온라인 필요.
- 서로 다른 필드·독립 레코드 변경은 자동 병합, 동일 필드 동시 수정은 사용자 버전 선택(Q19). 타이머 오프라인 동시 실행은 둘 다 충돌 후보로 보존 후 사용자 해결(Q82).
- 일상적인 동기화 상태 아이콘이나 상세 변경 로그 UI를 만들지 않음(Q109). 충돌 해결 및 실질적 오류 안내는 반드시 유지.

### 구현 제안(승인된 제품 요구가 아닌 기술적 세부)
- 프런트엔드: 기존 React + Vite + TypeScript, Tailwind CSS v4, lucide-react, recharts, vite-plugin-pwa 재사용. **Windows/iPad용 웹앱과 Android Capacitor APK는 단일 UI 코드를 공유**한다. 라우팅/상태 관리 패키지는 저장소 실사 후 결정. Android 네이티브 어댑터/앱 빌드 자산은 별도 관리.
- 서버: Cloudflare Pages Functions(또는 현재 저장소 배포 방식에 맞는 Cloudflare Workers API) + D1. 백엔드에서 로그인 주체를 검증해 사용자별 DB 조회/변경 권한을 확인.
- 로컬: IndexedDB/Dexie 기반 읽기 캐시 + 재시도 가능한 변경 작업 큐. 변경마다 안정적 UUID, `user_id`, 버전, 수정 주체, 서버 타임스탬프, 삭제 상태를 명확히 관리.
- Google 로그인 ID 토큰 서버 검증(서명·발행자·audience·만료), 인증 세션에는 `HttpOnly; Secure; SameSite` 쿠키를 우선 검토. Drive 권한은 최소 범위와 Picker 사용을 검토. 클라이언트에 백엔드 비밀키·장기 갱신 토큰 노출 금지.
- 타이머는 서버 측 계정 단일 활성 세션/소유권 확인. 오프라인·동시 수정은 잠정 이벤트로 구분하고, 정상 확정 기록 간 교집합이 없는지 서버에서도 검증.
- UI 우선 개발 시 가짜 데이터는 **테스트 전용 메모리 fixture**에만 두고, 실제 초기 DB/사용자 화면은 빈 상태로 유지.

## 14. 필수 검증 시나리오(Acceptance Tests)

1. `2026-11-21 02:00 KST`에 홈의 '오늘'=11/20, 시험 11/21은 D-1. 05:00부터 11/21 및 D-Day.
2. `11/20 04:30~05:30` 학습 기록 60분은 11/19 학습일 30분 + 11/20 학습일 30분. 원본 04:30~05:30 유지.
3. 실제 학습 기록이 기존 19:00~19:40과 신규 19:30~20:00으로 겹치면 저장 불가. 기록 수정 UI에서 어느 구간을 수정할지 제시.
4. 수학 50분→영어 전환 확인→영어 30분 + 휴식 10분이면 전체 자습 80분·휴식 10분. 과목별 시간 정확히 분리.
5. 계획 블록에서 시작해 과목을 바꾸면 새 과목 구간은 원래 계획과 연결되지 않는다. 계획 종료 후 타이머는 계속 실행.
6. 학원 수업 3시간 + 자습 2시간이면 전체 학습 통계는 5시간, **자습 시간 목표 실적은 2시간**.
7. 수능/내신 두 태그 세션 1시간은 각 필터에 등장하지만 전체는 1시간.
8. 하위 작업과 직접 연결된 문제집 Part가 각각 모두 완료되어야 상위 자동 완료. 수동 완료/취소 규칙 Q62/67 확인.
9. 학원 템플릿 변경 시 미래 미완료 주차에서 사용자가 직접 수정한 필드가 덮어써지지 않는다.
10. 이번 주 수업이 없으면 신규 숙제 생성 없음. 이미 만든 숙제 후 휴강이면 숙제 유지·다음 실제 수업일로 마감 연기.
11. 학원 강좌 삭제 후 완료된 숙제의 강좌/강사 등 확정된 역사 표시 유지.
12. 오답 목록 완료 확정 전에는 누락 문항 정답으로 간주하지 않음. 총 문항 수 변경 후 판정 재계산.
13. 문제집에 새 미완료 Part를 추가하면 전체 완료가 취소되고 시험 범위 추가 여부 확인.
14. 프로젝트 삭제→연결 할 일·하위 항목 휴지통→30일 내 복원 시 모두 관계 유지하여 복원.
15. Drive 접근 권한 철회 시 파일 연결 메타데이터 유지+접근 불가 표시. 앱 삭제로 Drive 실제 원본 삭제하지 않음.
16. JSON 복원 시 기존 앱 데이터 전체 대체를 사용자에게 명시하고 유효성 검사 및 안전 백업 후 복원.
17. Android APK 스마트폰 하단 메뉴/iPad·PC 웹앱 사이드바, 기본 일간 캘린더, 시스템 테마에 따른 라이트·다크 표시, 신규 계정 초기 데이터 0건.
18. 같은 계정으로 PC 웹앱 ↔ iPad 웹앱 ↔ Android APK 사이에서 계획/학습/시험 기록이 동기화되고 충돌 시 기존 해결 규칙 적용. Android의 Google 로그인·Drive 동의는 삽입형 WebView OAuth 없이 완료.
19. Android에서 APK를 설치·재실행·업데이트하고 화면 뒤로 가기·키보드·오프라인 데이터 재실행 복원 동작을 확인. 웹 버전 배포와 APK 업데이트가 독립적임을 검증.

## 15. 구현·검토 시 오해하면 안 되는 점

- **화면 우선(Q157A)**은 시각적 설계를 모두 마친 뒤 기능을 연결한다는 순서다. 다만 프런트엔드 상태 흐름·타입·컴포넌트 계약은 화면 단계부터 정의하여 재작성 비용을 줄인다.
- Q109에 따른 상시 동기화 표시 없음 ≠ 충돌/실패를 조용히 무시해도 됨.
- Q75C는 **Q84의 후속 명시적 수정으로 무효**. 겹치는 확정 공부 기록 저장 허용 금지.
- Q142A '반복 일정 삭제는 한 회차만' ≠ Q131C '반복 일정 수정의 적용 범위를 선택'.
- Q137A '수업 없는 주에 새 숙제 생성 없음' ≠ Q140A '이미 생성된 숙제는 휴강 후에도 유지'.
- Q58 완료/미완료만 제공 ≠ Q12 일일 완료량 목표의 내부 날짜 귀속 불필요. 구현 전 내부 날짜 메타데이터 처리 원칙 명시.
- 기존 Windows 개발 환경의 빌드가 성공했다는 과거 맥락만으로 현재 저장소·의존성 상태를 단정하지 않는다. Claude Code가 직접 실사한다.
